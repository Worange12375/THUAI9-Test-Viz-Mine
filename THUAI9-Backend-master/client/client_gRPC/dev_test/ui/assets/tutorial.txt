THUAI9 测试端使用教程（草稿版）
- 本文件位置：dev_test/ui/assets/tutorial.txt

【1. 快速开始】
1) 启动：运行 dev_test/ui/main_ui.py
2) 进入测试：每次运行后 或者 选定“模式选择”后 会弹出 选择数据源 窗口。
 	 - 后端模式（自定义/职业）：使用后端的真实玩法逻辑，
	        部分后端未完整实现的部分单独在测试端做了实现。
	 - mock 模式：回放/固定样例数据集（暂时弃置）

3) 配置属性：选定了后端模式后，会弹出“属性设置”窗口，可以配置初始属性。
	 - 当然你可以选择“一键开始”，快速使用开发者设定的经典对局进行游戏。
	 - 注意点击“应用”，正式开始游戏。

4) 游戏对局：点击“棋子行动”，操作棋子进行行动（如移动、攻击、法术）。
	 - 流程统一说明：先选定行动类型，再选定目标（或坐标）
	 	再点击“确认行动”才会真正执行，点击“行动完毕”结束行动回合。
	 - 行动限制：行动受行动位和法术位限制，行动位每回合更新，法术位不恢复。
	 	行动都有范围限制，超出范围则无法行动。
		对于锁定型行动，测试添加了标记符号辅助判断是否在行动范围内
	 		体现为在对象左上角显示一个标靶图案，
			若没有，则代表当前对象超出范围。

	 - 移动：可通过输入目标坐标或点击“棋盘选点”按钮在棋盘上直接选点。
	 	注意：棋盘选点每次只接受一个坐标，如果想更换请重点一次“棋盘选点”

	 - 攻击：攻击类行动都是锁定型行动，需要选定攻击的对象
	 	右侧的下拉框可以选定“物理攻击”、“法术攻击”、“定制攻击”（测试用）
		其中对于非法师职业来说“物理攻击”可视为普攻
		对于法师来说“法术攻击”可视为普攻
		由于这些攻击与天赋属性、装备等相关，
		因此通常来说使用错误类别的攻击往往无法造成有效伤害（未命中或伤害低）

		定制攻击是专门为测试人员设计的，可以无视对方防御造成设定的真伤伤害

	 - 法术：（1）法术分为锁定型和非锁定型
	 	锁定型：需要选定法术的施用对象，如“箭击”需要选定法术施用目标棋子
	 	非锁定型：不需要选定目标，如“火球术”只用选定施用的中心坐标
			（2）法术分为延时型和非延时型
	 	非延时型：立即生效，如“火球术”立即造成伤害
	 	延时型：如“陷阱”是一个持续两回合的法术
			（3）法术有作用范围，且范围有两种意义
	 	施用范围：法术施用前选定目标的范围，决定是否有足够的距离对目标施用法术
	 	影响范围：法术施用后能造成伤害的范围，即群伤，范围内的棋子都会受到影响

5) 属性设置：在“属性设置”窗口可以设置棋子属性，点击“应用”后生效。
	 - 自定义模式下属性都可更改；职业模式下只能更改坐标
	 - 两种模式都能进行地图和行动更改
	 	- 地图更改是修改棋盘某格的高度
		- 行动更改是修改攻击/法术的命中或伤害公式

6) 回放模式：还在开发中，敬请期待。

7) 系统设置：在“系统设置”窗口可以设置一些玩法参数，详细可以看实际窗口内说明。
	 - 你也能在这里找到这份使用教程

8) 退出测试：即退出测试程序


【2. 数据源与对局模式说明】
- 后端模式（自定义/职业）
	- 适合验证：后端规则实现、行动结算、死亡/胜负判定

- mock 模式（暂时搁置）
	- 适合验证：UI 展示、回放节奏、固定输入输出
	- 选择数据集：在弹窗中选择 mock dataset

【3. 系统设置（System Settings）】
3.1 综合设置
- 右侧信息展示区：按类别显示/隐藏（重要/回合/玩家/系统/默认）
- 投掷必定命中：将指定 d20 投掷强制为 20（仅测试端覆盖，不改后端算法）
	- 攻击命中检定（物理/普通法术）
	- 死亡检定（HP→0）
	- 先攻（行动队列）

3.2 玩法设计
- 在这里可以设置“仅单次程序运行生效”的玩法更改，这些更改数据都是临时的
	不会更改后端的玩法，而是在测试端做临时覆盖。退出程序后修改不保留
	（未来会出设置保存、一键导入系统）
- 全局：
		目前只包含濒死系统，这是后端并没有完全实现的部分，测试端按照
		玩法文档做了单独实现，相关叙述直接见设置页
- 属性；
		目前只包含天赋梯度设置，这里可以修改天赋计算的梯度
- 法术：
		目前只用于配置棋子的法术池，由于后端实现并不完善，测试端做了
		简单覆盖。
- 攻击/职业相关设置还未加入。

【4. 常见问题（FAQ）】
Q: 我改了设置但没生效？
A: 确认是否点击“应用”；大部分页面在修改后都会提示“未应用”，请及时点击应用
	如果没有应用就关闭窗口，那么相关设置会恢复为上一次应用的状态。

Q: 我只想在右侧信息展示区看关键日志信息？
A: 在“系统设置→综合设置”里把非关键类别隐藏。

Q: 出现异常/崩溃怎么定位？
A: 先看右侧信息展示区；再用 VS Code Debug 运行 main_ui.py 查看 traceback。

Q：到哪里反馈测试端的bug或者优化建议？
